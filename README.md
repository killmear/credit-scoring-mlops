# Кредитный скоринг: ML-пайплайн

Итоговый проект по автоматизации разработки и тестирования моделей машинного обучения.
Автор: Владимир Шершнев.

Модель оценивает вероятность дефолта клиента в следующем месяце. Данные —
[Default of Credit Card Clients, UCI](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients),
30 000 записей, лицензия CC BY 4.0, автор I-Cheng Yeh, DOI 10.24432/C55S3H.

## Результаты

Данные разделены на train/test 80/20 со стратификацией и seed 42. На train сравнены
пять конфигураций LogisticRegression и HistGradientBoosting по трём фолдам.
Выбран HistGradientBoosting: 7 листьев, 120 итераций, learning_rate 0,08.
Порог классификации 0,5 зафиксирован до оценки на test.

| Метрика на test | Значение |
| --- | ---: |
| ROC-AUC | 0,7798 |
| Precision | 0,6681 |
| Recall | 0,3595 |
| F1 | 0,4674 |

Полный разбор с выполненными ячейками и графиками — в [ноутбуке](notebooks/PJ_MLOps_CreditScoring_SHERSHNEV_killmear.ipynb).

## Запуск

Нужны Python 3.11 и Git; для контейнера — Docker. Все команды выполняются из корня
клонированного репозитория.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
dvc repro
python -m src.verify
```

DVC скачает исходник с UCI, проверит SHA-256, подготовит выборки и обучит модель.
Данные и модель версионируются через dvc.lock; в Git они не включены.
Удалённое DVC-хранилище не используется: новый клон восстанавливает артефакты через
`dvc repro`. Повторный запуск без изменений пропускает готовые стадии.

```bash
docker build -t credit-scoring .
docker run --rm -p 127.0.0.1:8000:8000 credit-scoring
```

В Windows также можно выполнить `./run-docker.ps1`.
Откройте http://localhost:8000 — выбор из 10 клиентов, исходные данные и прогноз.
На `/details` показан последний запрос и ответ в текущей вкладке, на `/docs` — Swagger.
Примеры — первые 10 строк фиксированной тестовой выборки без целевой переменной,
без отбора по прогнозам модели.

Без Docker: `python -m uvicorn src.api:app --host 127.0.0.1 --port 8000`.

## Проверки и мониторинг

```bash
python -m src.validation
pytest -q
black --check --line-length 100 src tests
flake8 src tests
python -m src.monitor --url http://127.0.0.1:8000
```

Great Expectations проверяет структуру, типы, пропуски и диапазоны входных данных.
Тесты проверяют предобработку, метрики, сериализацию модели и контракт API.
GitHub Actions воспроизводит DVC-пайплайн, выполняет проверки и собирает Docker,
после чего отправляет в контейнер реальные HTTP-запросы.

Мониторинг сравнивает вероятности на train и 500 клиентах test: PSI = 0,0214.
Это имитация нового потока на исторических данных, а не проверка дрейфа в эксплуатации.

## Эксперименты

```bash
mlflow ui --backend-store-uri sqlite:///mlflow.db --host 127.0.0.1 --port 5017
```

Откройте http://localhost:5017, эксперимент `credit-scoring`, вкладку Training runs.
Записываются параметры, CV-метрики и модели; для выбранной модели — также test-метрики
и ROC-кривая. Скриншот анализа находится в `reports/mlflow-ui.png`.
Текущие пять run_id перечислены в `reports/metrics.json`; при воспроизведении они обновятся.

Ноутбук читает готовые артефакты. Для повторного выполнения сначала запустите
`dvc repro`, `python -m src.verify` и мониторинг работающего API.

## Структура

- `src/` — подготовка, валидация, обучение, API и мониторинг.
- `src/static/` — демонстрационный интерфейс.
- `tests/` — модульные тесты и проверки API.
- `notebooks/` — анализ данных и результатов.
- `reports/` — метрики и иллюстрации.
- `dvc.yaml` — стадии download → prepare → train.
- `.github/workflows/checks.yml` — автоматические проверки.

## Ограничения

При пороге 0,5 полнота составляет 0,3595. Для прикладного использования нужны оценка
цены ошибок, подбор порога на validation и проверка калибровки и устойчивости во времени.
Предобработка обучается внутри фолдов Pipeline; ID и целевая переменная не входят
в признаки. Необычные категории EDUCATION 0/5/6 и MARRIAGE 0 сохранены отдельно,
отрицательные счета допускаются.
